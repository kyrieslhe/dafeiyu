# 微信聊天节奏

## 研究与设计取舍

即时聊天的一次话轮可以包含多条消息；回答也不必逐条按原顺序复刻，而可按话题相关性组织。参见 [König（2019），SMS 与 WhatsApp 的话轮组织](https://journals.sagepub.com/doi/10.1177/1750481319868853)。

[Martin 等（2026），WhatsApp 与 Instagram 回复时长研究，预印本](https://arxiv.org/abs/2605.03687)观察到回复速度存在个体差异与双方的节奏关联，不支持统一的“像人就必须慢几秒”规则。[Stephanie2（2026），聊天等待与节奏的模型研究，预印本](https://arxiv.org/abs/2601.05657)也指出：将一次生成机械切块不等于自然互动，等待与发送决策需要共同考虑。后者是 AI 系统研究，不是普遍人类行为定律。

据此落实七项产品行为：

1. 同一用户连续补充可构成一个话轮，统一理解，而非每条都完整答一次。
2. 用短暂安静间隔判断是否说完，同时给持续连发设置最长等待界限。
3. 回复可是一段，也可按自然语义分为两到三条；不强制固定句数。
4. 有界消息间隔给对方继续说话的机会，不模拟虚假的在线状态或正在输入。
5. 新补充到来时放弃过时回复，或停止后续未发送段落，优先接新信息。
6. 长说明、列表、代码保持完整，正式话题不强拆成零碎聊天泡。
7. 主动分享来自真实发现，遵守白天、频率、额度与明确停止；晚安、忙碌、收尾场景不追问催回复。

这些是基于研究的设计推断，具体数值是可调整的工程初值，不是研究测得的人类标准。

## 当前实现

- 微信 SDK 的拉取循环逐条等待处理完成，因此不能只在同步回复钩子里 sleep 实现连发合并。普通文字先经过原身份绑定/稳定消息编号检查，再落入本机持久队列，立即释放接收；单独 conversation 服务处理聊天，研究 worker 不会阻塞文字接收。
- 默认安静 1.8 秒后处理，一批最多 12 条、12000 字符；持续连发最多等 8 秒。管理命令作为独立话轮排队，不和前后聊天拼成一个命令。
- 一次话轮只生成一次回复。最多三段明确的短段落可分条发送，间隔约 0.6–2.5 秒；超过 900 字符、含代码或列表保持完整。不是逐标点硬切。
- 生成期间又收到文字时不发送旧稿；发送分段期间收到文字时停发剩余段落。没有实际发出的草稿不作为已说过的话保存在对话记忆。
- 超时/不确定发送和中断生成不盲目重试。已绑定身份改变后不向旧对象继续发。队列最多保留 30 天；清空/遗忘会清理已处理缓存，后续排队的用户新消息仍按顺序处理。
- 图片、语音等附件仍走现有同步受限路径，尚未统一到这个文字队列，不声称所有混合媒体连发都已覆盖。

## 主动消息修正

旧应用自己添加了“最近 90 秒必须收到用户消息”的条件；当前固定版本腾讯 SDK 存储并复用会话上下文，没有这个应用固定时限。移除此条件，由 SDK 按现有会话发起一次实际发送。平台明确返回上下文失效才等待新来信；认证失败或发送结果不确定停止重试。没有读取、迁移或另存 SDK 凭据。

实际结果仍取决于微信平台是否接受该上下文，不能保证无限期主动联系。探索计划、每日分享上限、23:00–08:00 静默、暂停和身份绑定条件保持生效；有排队或进行中的文字聊天时不插入后台发现通知。

## 验证边界

测试覆盖身份校验后的真实本机入队、连发一次调用、生成中补充、分段中打断、发送超时不重播、命令边界和一小时前来信仍可尝试主动分享。网络发送使用模拟 runner，不发送测试微信，不将接口接受当作用户收到或已读。真实微信来回和实际分泡显示仍需日常使用验证。

## 临时可用性与分享时机

明确说晚安、去睡觉时，后台发现等到香港时间次日09:00或你再次来信；明确说去忙、开会、跑步、上课时暂缓两小时。疑问句、否定和仅提及这些词不会据此推断你要离开。说别打扰时等你新来信再恢复，也可 `/quiet 1–1440` 设置分钟、`/quiet off` 恢复。它只是临时投递状态，不写入用户画像或长期事实，不对情绪作推断。明确安排的一次提醒保留原投递策略。

普通研究/探索发现也会避开刚结束的文字聊天两分钟；有正在排队的聊天时继续暂缓。等待不会标成已送达或已读，也不需要额外模型调用。语义识别为有限中文规则，不承诺理解所有表达。

## 补充、取消与清空

生成过程中收到新补充或明确控制命令时，Codex 后端在取消检查点停止过时生成，发送前仍复核身份和新消息。短时连续取消后，合并窗口从1.8秒适度放宽至最多4秒，减少连发期间反复启动模型；最长等待仍为8秒。`/pause`、`/resume`、`/cancel`、`/quiet`、关闭自主探索等明确控制可立即处理，不等闲聊生成结束；清空与遗忘仍按顺序处理，避免生成中重新写回已清除内容。

清空或遗忘设置关系上下文重置点，不再自动注入重置前的任务摘要；原任务报告不删除，用户明确用 `/result` 查询时仍可读取。换绑后，旧身份的待处理文字被丢弃，不阻塞新确认身份的队列。上述取消不代表已送出的消息可以撤回，也不能保证平台立即停止在途发送。
