# 让大肥鱼持续在线

持续在线需要服务所在设备接电、联网且保持运行。建议先用下面的 Mac 当前会话监管；长期陪伴用独立常开设备，让个人笔记本可以随时带走。电脑关机、合盖或断网时不能保证收消息，也不把进程存在等同于微信可达。

## Mac 当前登录会话

```sh
python3 scripts/stay_online.py start --keep-awake
python3 scripts/stay_online.py status
python3 scripts/services.py status
```

这会启动独立于终端的监管进程。macOS 下 `--keep-awake` 使用系统 `/usr/bin/caffeinate -s`，**只在接电时防止系统休眠**；允许屏幕休眠，拔电后不阻止正常省电，不修改系统全局电源配置，也不绕过合盖或手动休眠。没有这个选项时仅监管服务。其他系统不创建 macOS 唤醒请求。

监管每轮检查本项目 gateway/worker/conversation 进程、本地 HTTP 健康端点和微信渠道 `running` 状态；不调用模型、不发送探测消息、不读取聊天。正常轮询约 30 秒，探测本身有时限。进程消失会尝试补启动；连续三次健康探测失败会重启服务；观察到超过 120 秒的主机运行间隙会尝试重连。后台服务重启可能中断正在处理的消息，不自动重放。

一次修复后至少等待 60 秒；十分钟内最多自动修复三次，之后写停止标记并停止自动恢复，避免无限重启。请先检查私人 `var/service-supervisor.log`、网关日志和网络，再用 `services.py start` 明确恢复。监管不会因为用户长时间不发消息而重启。渠道 `running` 只是进程报告，不是微信端到端可达证据；DNS/平台持续故障仍需要排查，不能保证自动修好。

停止当前会话常驻并释放唤醒请求：

```sh
python3 scripts/stay_online.py stop
```

`services.py stop` 也会阻止监管恢复服务，监管下轮检查时释放唤醒请求。若需要改变 `--keep-awake` 选项，先 stop 再 start。重复 start 不生成多个监管器；同一项目的登录项与当前会话监管共用排他锁。

**这是当前登录会话的后台运行，不是已经安装成功的开机自启。** 退出登录、重启后需要重新运行。登录 LaunchAgent 仍见 [恢复与常驻](recovery.md)；项目位于受保护目录时，macOS 可能要求本机文件访问授权。先停止当前会话监管，再安装登录项。不要以注册成功冒充真实登录启动验证。

## 长期部署选择

- 闲置 Mac mini：迁移改动少，仍需电源、网络、登录服务权限，以及 Docker 和官方模型/微信登录的真实检查。
- 独立 Linux 迷你主机：可以用 systemd 管理服务，适合长期运行；需在目标机重新完成官方认证，验证微信插件、Docker 与重启恢复。
- 云服务器：不受家中停电和笔记本休眠影响，但有持续费用，需要验证微信平台可达、模型登录及主机安全。当前没有自动购买、开通或上传私人数据。

新设备使用最新加密备份恢复到新目录，先验证记忆和任务；按官方流程重新登录 Codex 和微信。不要直接拷贝 OAuth token 或微信凭据。恢复密钥与加密备份分开保管；仅在同一台机器上备份不能应对整机损坏。见 [恢复指南](recovery.md)。

Linux 用户服务和真实目标机验收步骤见 [常开 Linux 部署](linux-host.md)。健康采样会过期，不把旧的健康记录当作当前在线；个人 Mac 的系统文件权限和供电条件仍需分别满足。
