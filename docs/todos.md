# 微信里的个人待办

这是你的生活清单，和 `/tasks` 后台研究任务、长期记忆分开保存。不自动把普通生活叙述加入清单，也不自动设置提醒或主动催办。

直接发文字即可，不需要模型调用：

```text
加个待办：买牛奶
帮我添加待办：归还图书
看看我的待办
完成待办 1
撤销完成待办 1
删除待办 1
查看已完成待办
```

也支持 `/todo add 内容`、`/todo done 编号`、`/todo reopen 编号`、`/todo delete 编号`。`/todo` 查看未完成，`/todo completed` 查看已完成，`/todo all` 查看全部；每页20条，第二页如 `/todo list 2`。回复使用实际保存的编号与状态，不采纳模型声称的执行结果。

自然变化的清单查询可由现有聊天模型路由到只读查询，这种表达仍会消耗正常聊天额度。模型没有修改清单的动作；改动需发送上面的明确文字格式。语音转写可以查询，修改需文字确认；附图请求不直接执行清单改动。连续发送的明确清单指令分别处理，避免合并成一句普通聊天；重复入站消息由已有消息编号去重，重复的未完成内容也不会重复添加。

每条最多500字符，总共200条，完成事项保留至你删除；相同未完成内容按 Unicode 规范化与大小写去重。重新恢复时若已有同内容未完成项，会拒绝重复恢复。已删除编号不会复用，避免旧编号误改新事项。密码、密钥类内容沿用现有本机拒绝规则。

数据只保存在私人 SQLite 库，正常加密备份会包含清单。`/clear` 只清聊天，`/forget` 针对明确记忆；二者不删除待办，清单用 `delete` 单独管理。删除清单条目不会擦除微信消息、此前的查询回复、原始入站记录或旧备份；需要时分别清理。清单原文不自动进入普通聊天或公开搜索上下文。

测试包括真实临时 SQLite 持久化及模拟微信队列/发送器；模拟发送接受不证明真实微信送达。功能不要求常开设备；离线时不会接受或执行微信请求。
